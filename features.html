Features

The living ledger of what therapy-aid does and doesn't do yet. A weekly-therapy memory for one person: record or paste each session, keep the problems it surfaces, and ask questions of the whole history. Updated in the same commit as every change (CLAUDE.md hard rule 3). Live at therapy-aid.elephant-trench.ts.net — tailnet only.

Status: v1 — sessions, problems, focus, journal, chat, settings  ·  Last updated: 2026-11-03
How to read this page. A green tick is built, tested, and part of the product. A grey box is not there yet, listed so nobody assumes otherwise. The AI features need ANTHROPIC_API_KEY (and recordings need DEEPGRAM_API_KEY) in ~/therapy-aid.env on the Pi; without them the app runs and says exactly what to set.
1

Sessions

Two ways in, one record out: a title, an overview, key points, what David suggested, and the effect on your problems.

  • ✓ Record a session in the browser (phone or laptop). Audio uploads in 30-second chunks as you talk, in order, with retries; a progress count shows what has landed. Needs the HTTPS tailnet address (browsers only allow the microphone on a secure page). Leaving the Record screen mid-session stops and saves what was captured rather than discarding it; closing the tab asks first.
  • ✓ Transcription with speaker separation (Deepgram); the summary works out which speaker is the therapist from what is said.
  • ✓ Add notes instead: paste or type notes or a summary for any past date.
  • ✓ Summary: title, overview, key points, therapist advice. Written for you to read next week.
  • ✓ Live progress on the session page (uploaded, transcribing, summarizing, ready); a failure shows the reason and a Retry that resumes at the step that failed.
  • ✓ Sessions list grouped by month; edit a session's date or title; delete with confirmation (removes its audio).
  • ✓ Interrupted work survives an API restart: stuck sessions are re-queued at boot.
  • Playing the audio back in the app (the file is kept on the Pi, but there is no player).
  • Resuming a recording after the browser tab is closed or reloaded. Chunks already uploaded are kept, but there is no screen to finish that session.
  • Hand-editing a generated summary.
  • Uploading an existing audio file instead of recording live.
2

Problems

The big-picture threads that persist across sessions.

  • ✓ Every session is mapped onto your existing problems (progress notes) or opens a new one for a durable theme; a note says what changed this session.
  • ✓ Problem page with a dated timeline of notes, each linked to the session it came from.
  • ✓ Create, edit, add your own notes, resolve, reopen, discard (destructive actions ask first).
  • ✓ Stale check: a problem not discussed or reviewed for 30 days asks “still relevant?” on Home, with Keep or Discard.
  • Merging two problems that turned out to be the same one.
  • Charts or trends over time per problem (the timeline is text for now).
3

Focus

  • ✓ Home banner: “what to focus on right now” — a headline and up to three items, each with why and one concrete action for this week.
  • ✓ Regenerated automatically after every session, and on demand with Refresh.
  • ✓ Home also shows the latest session and one-tap actions: record, add notes, write in the journal.
  • Focus history view (older snapshots are stored but not browsable).
  • Reminders or notifications before a session.
4

Journal

  • ✓ Entries by date, with an editor that autosaves as you type and says when it has saved.
  • ✓ “I have an idea…”: on request, an insight on the draft that connects it to recent therapy sessions and entries, with David's advice taking priority. Never generated on its own; past insights stay with the entry.
  • ✓ Seedable with your history through the import script.
  • Photos or attachments in entries.
  • Reminders or streaks. Deliberately absent.
5

Chat

  • ✓ A chatbot that knows your sessions, problems, focus and journal, weighs therapy over journal, cites which session or entry it is drawing on, and says so when the material does not cover something.
  • ✓ Looks things up first (full-text search on your question) and can search and open sessions and entries to follow up.
  • ✓ Multiple threads; create, switch, delete; Enter sends, Shift+Enter adds a line; errors show inline with a retry.
  • Streaming replies. The answer arrives whole after a thinking indicator.
  • Voice input or spoken replies.
  • A standalone search page (chat is the way to search today).
6

Settings & cost

  • ✓ “About me” profile that every prompt includes, editable in the app.
  • ✓ Shows who you are signed in as.
  • ✓ AI usage: per task, the model, calls, tokens and estimated dollars since the API last started.
  • ✓ Per-task model routing (cheaper models where quality holds), prompt caching, and env overrides for any task's model and effort.
  • Usage that survives a restart or shows month-to-date (totals are in memory).
  • Exporting your data (sessions, journal, problems) as files.
7

Platform, hosting & safety

  • ✓ Bun workspace: backend (Hono), frontend (Vite + React 18), packages/shared types.
  • ✓ SQLite (bun:sqlite + Drizzle), idempotent DDL applied at boot from backend/db-schemas/; full-text search with FTS5.
  • ✓ Docker Compose on the Raspberry Pi: api, web (nginx: SPA, /api proxy, 50 MB bodies, 10-minute timeouts), ts (Tailscale sidecar).
  • ✓ Served over HTTPS at therapy-aid.elephant-trench.ts.net, tailnet only (Funnel off, no public ports).
  • ✓ Sign-in: only the one allowed Tailscale login gets in; unset means everything is rejected, not allowed. /health stays public.
  • ✓ Secrets in ~/therapy-aid.env on the Pi, passed through compose; recordings on the same volume as the database.
  • ✓ Daily SQLite snapshots (VACUUM INTO, integrity-checked, 30 kept) in ~/therapy-aid-backups/; /api/health reports backup_ok.
  • ✓ scripts/import-seed.ts: imports profile, journal and past therapy notes over HTTP, in order, resumable and idempotent.
  • ✓ Model eval harness, bun run eval (scripts/eval-models.ts): the real prompts on the seed notes per model, outputs and costs.md in the gitignored eval-out/; --judge has Opus grade the cheaper models.
  • Run the eval and settle TASK_MODELS: the per-task models are still the initial defaults, not yet confirmed by an eval.
  • ✓ /ship skill: commit → PR → redeploy, verified by the live revision on /api/health; the Pi's secrets and seeding runbooks live there.
  • ✓ Architecture tests: layering import bans and the 200-line file cap (code, docs/, scripts/ and this page). See Architecture and Operations.
  • Backing up the recordings (snapshots cover the database only).
  • Copying snapshots off the Pi (they share its SD card today).
  • CI (GitHub Actions running bun run test on PRs).
  • Installable PWA and offline use.
