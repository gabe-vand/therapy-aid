1

Tokens and the three text colours

Every colour is a custom property in src/styles/tokens.css, defined once for light and once for dark. Never a hex literal anywhere else; a new colour is a new token. Tailwind v4 is for layout utilities only.

  • Surfaces: --paper (page), --surface (cards, panes, inputs), --surface-2 (sidebar, hover, subtle fills), --surface-3 (pressed, selected). Lines: --line (hairlines), --line-2 (input borders).
  • Text: --ink, --ink-2 and --muted do nearly all the work (three text colours); --faint is for placeholders and disabled only. Hierarchy comes from weight and these colours, not from size: headings are 15–20px semibold.
  • Accent and status: --accent, --accent-hover, --accent-soft, --on-accent; --ok, --warn, --danger each with a -soft fill (and --on-danger). Also --focus, --overlay, --shadow-sm/md/lg, --skeleton, --r-sm/md/lg/xl, --font, --font-mono.
  • Page-scoped CSS never travels: a reusable component imports its own CSS and never borrows another page's classes. Shared CSS is split by concern under components/ui/ (ui-buttons, -forms, -layout, -overlays, -surfaces).
2

Theme mechanism

  • The theme is data-theme="light|dark" on <html>; tokens.css keys on it. The preference is light, dark or system, stored in localStorage['ta-theme'], default light. Storage access is always guarded (private mode throws).
  • public/theme.js is a classic script loaded in index.html before the module, so the first paint is already right. It is a file, not inline, because the Pi's CSP is script-src 'self'. It duplicates the key, values and default of services/theme.ts — keep the two in sync.
  • services/theme.ts holds the pure logic (read, resolve, apply, THEME_KEY); services/hooks/use-theme.ts (useTheme) exposes preference, resolved and set_preference, follows the OS live while on system, and keeps every mounted toggle in sync.
  • The switch is components/shell/ThemeToggle.tsx: icons only in the sidebar, show_labels in Settings → Appearance. Tests use tests/helpers/hlp-theme.ts (stub_dark_os, reset_theme).
3

Page widths

Every page renders inside <Page width="…"> (components/ui/Page.tsx); the shell's <main> is full-bleed.

  • reading — 760px column for one thing to read or fill in (details, forms, Settings).
  • wide (default) — 1120px for lists and dashboards.
  • full — no max-width and no padding, for split panes (Journal, Chat). On desktop a full page owns its scroll: it is the whole main height and each pane scrolls on its own. On phones it lets the window scroll and shows one pane at a time.
  • Padding: 32px/40px on desktop, 20px top and 16px sides on phones. Sticky offsets on mobile use the shell's --ta-topbar-h and --ta-tabbar-h.

Primitives and icons

Use these before writing markup of your own (all under components/ui/):

  • Button / ButtonLink (primary, secondary, ghost, danger; sm, md, lg) and IconButton (aria-label required, aria-pressed for toggles).
  • Card, Chip, Skeleton / Loading; PageHeader, BackLink, EmptyState, ErrorState (role=alert).
  • SegmentedControl (a labelled group of aria-pressed buttons), Menu (the overflow “…”), ConfirmDialog (a bottom sheet on phones), and the .ta-input class for inputs and textareas.
  • Icons are lucide-react: 16px in chrome, 18–20px in content. No emoji or text glyphs (+, arrows, triangles) in UI chrome.
5

Mobile rules

The owner uses this on his phone. Design every screen at 390px first, then widen.

  • One column below 768px and nothing overflows horizontally (wide tables scroll inside their own wrapper).
  • Anything tapped is at least 40px tall. Inputs and the editor use 16px text, or iOS zooms on focus.
  • Respect env(safe-area-inset-*) on the top bar, tab bar and every fixed element; the chat composer sits above the tab bar.
  • Dialogs become bottom sheets below 768px (full width, rounded top corners). Headers wrap, with actions dropping below the title.
  • Journal and Chat show one pane at a time on phones (list, then document or conversation, with a back control).
6

The journal editor — Markdown is the stored format

  • The journal editor is TipTap v3 (@tiptap/react, starter-kit, @tiptap/markdown) in components/journal/RichEditor.tsx: bold, italic, strike, headings, lists, quotes.
  • The entry body stays a Markdown string. The backend, full-text search and the AI context pack are untouched. Anything that previews a body (first_line()) must strip Markdown syntax.
  • Read-only Markdown (summaries, chat answers) goes through components/markdown/Markdown.tsx, image-free by design.
  • Page tests vi.mock('@/components/journal/RichEditor') with a plain textarea taking the same props, so autosave tests stay simple; tests/components/journal/RichEditor.test.tsx exercises the real editor. The journal route is code-split in App.tsx so TipTap loads only when the journal opens.
